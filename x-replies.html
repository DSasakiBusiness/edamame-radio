X返信案の作成について

@edamamedenpaky への返信に、AIで返信の下書きを作る仕組みの説明

最終更新: 2026年10月12日

X アカウント @edamamedenpaky で使う返信案作成ツールについて、扱うデータを説明するページです。このページの作成時点では、この機能はまだ動かしていません。返信の読み取り、案の作成、送信のどれも始めていません。

しくみの概要

@edamamedenpaky の投稿に直接返信をいただくと、ツールがその返信と元の投稿を読み取り、公開設定を確かめてから、外部の AI に返信の下書き（返信案）を作らせます。案は運営者の手元の確認画面にだけ表示されます。運営者が中身を読み、必要なら書き直してから、X の投稿画面を開いて自分で投稿ボタンを押します。ツールが X に自動で投稿することはありません。

このページの適用範囲

このページは X の返信案機能だけについての説明です。トップページのプライバシーポリシーは YouTube のライブ配信で使うアプリケーションについて書かれたもので、X のこの機能には当てはまりません。トップページにある「外部サービスへの転送は行いません」という記述や、ライブチャットの !forget による削除は、この機能には適用されません。この機能では、下で説明するとおり返信の本文を外部の AI サービスへ送ります。

対象になる返信

対象は @edamamedenpaky 自身の投稿への直接の返信だけです。ツールは次の条件をすべて満たす返信だけを案の作成に回します。

  • 返信先がひとつに決まり、その返信先の投稿の投稿者が @edamamedenpaky 本人であること
  • 返信した人と元の投稿の投稿者の両方について、読み取った時点で公開と確認できること（下の「公開設定の確認と、その限界」を参照）
  • X が判定した言語が日本語か英語であること
  • 先頭の @ユーザー名 を除いた本文が空でなく、280文字以内であること
  • 本文に URL（http や www で始まるもの、t.co のリンク）、メールアドレス、10桁以上の数字の並び、@ユーザー名、「住所」「電話」「メール」「メアド」「LINE」「口座」「パスワード」「DM」などの語（英語の address、phone、email、password を含む）が入っていないこと
  • 返信先になった元の投稿の本文も、上の2つの条件を満たすこと

条件に合わないものは AI に送りません。ただのメンション、ほかの人あての返信、@edamamedenpaky 自身の投稿は、処理済みとしてポストIDだけを手元に記録します。返信先が決まらない、言語が違う、上の語を含む、といった理由で外した返信は、ポストIDと理由を表す短い分類名を手元に記録します。

公開設定の確認と、その限界

メンションと元の投稿を読み取るとき、ツールは投稿者のアカウントの公開設定も一緒に返すよう X API に求めます。返信した人と元の投稿の投稿者のそれぞれについて、X が「鍵をかけていない」と返し、アカウントにも投稿にも閲覧制限の情報（国や地域による非表示、フォロワー限定など）が付いていない場合だけ、本文を案の作成に回します。

鍵がかかっている、公開設定の値が返ってこない、閲覧制限の情報が付いている、といった場合は「公開と確認できなかった」ものとして扱い、本文は保存せず、AI にも送りません。投稿のデータの形に問題がなければ、ポストID、記録した時刻、理由の分類名を手元のファイルに残します。その回の処理が最後まで進めば、ポストIDは処理済みの一覧にも入ります。このファイルに件数の上限はなく、自動では消えません。応答の形そのものが想定と違うときは、本文を使わずにその回の処理を止め、運営者が確認するまで再開しません。

返信した人の側で確認できなかった返信は、運営者の確認画面にある人手確認の一覧には出ません。元の投稿の側で確認できなかった場合は、記録には元の投稿のポストIDが入り、返信のポストIDは、元の投稿を利用できない返信として人手確認の一覧に載ります。一覧に添えて表示される理由は、元の投稿の本文が空だった場合と同じ短い分類名です（言語など別の条件で先に外れた場合は、その条件の分類名になります）。

公開と確認できなかった投稿のデータに、ポストIDや投稿者IDが正しい形になっていない、本文の欄が想定した形で入っていない、といった問題がある場合は扱いが変わります。ツールはその投稿の記録を書かず、本文も使わないまま、公開の投稿に同じ問題があったときと同じようにその回の処理を止めます。このときは、その回に読み取ったポストIDを処理済みの一覧に加えず、次に読み取りを始める位置も進めません。この場合も、運営者が確認するまで再開しません。

この確認は、読み取ったその時点で X API が返した内容だけを根拠にしています。読み取った後で相手が鍵をかけたり、投稿を削除したり、表示が制限されたりしても、その変化は作成済みの返信案や手元の記録には反映されません。X API の説明では、投稿の閲覧範囲の情報は広告として配信された投稿にしか返らないとされています。そのため、投稿ごとに付けられる閲覧制限のすべてを、X API の応答から見分けられるとは限りません。このツールが公開された情報だけを扱うことを、完全に保証するものではありません。

X から読み取る情報

X API は読み取り（GET）だけを使い、@edamamedenpaky のアカウント権限で次の情報を読み取ります。1回の読み取りで扱うメンションは最大5件です。

  • @edamamedenpaky あてのメンション: ポストID、本文（長文ポストは全文）、投稿者のユーザーID、返信先のユーザーID、参照しているポストのID、言語、会話ID、投稿日時、閲覧制限の情報、投稿者のアカウントの公開設定
  • 返信先になっている元の投稿: ポストID、本文、投稿者のユーザーID、閲覧制限の情報、投稿者のアカウントの公開設定
  • 運営者自身のアカウントのユーザーIDとユーザー名（正しいアカウントで動いているかの確認用）

公開設定を一緒に求めると、X の応答には投稿者の表示名とユーザー名（@ で始まる名前）も含まれてきます。ツールが判定に使うのはユーザーIDと公開設定の値だけで、表示名とユーザー名は保存せず、AI にも送りません。自己紹介、アイコン、フォロワー数といったほかのプロフィール項目は求めていません。ダイレクトメッセージも読み取りません。ただし、返信の本文に書かれた @ユーザー名 は本文の一部なので、確認画面に表示するために保存する本文には残ります。AI に送る本文には @ユーザー名 が入らないようにしています。

ツールが呼び出す X API は上の3種類の読み取りだけで、投稿、いいね、リポスト、DM の送信を行う処理はありません。

使う目的

読み取った情報は、返信案を作るため、案の対象にするかどうかを判定するため（公開設定の確認を含みます）、同じ返信を二度処理しないため、X API と AI の利用量を上限内に収めるために使います。

利用量は、運営者の手元の台帳で上限を決め、読み取りや AI への依頼の前に見込み額を予約して管理しています。公開設定を確かめるためのアカウント情報の読み取りも、同じ上限の中で予約します。これは手元での見積もりで、X や AI の提供元から実際に請求される額を保証するものではありません。

AI に送る内容

案の作成には外部の AI サービスを使います。稼働時の設定では、OpenAI のモデルを Codex 経由で使う予定です。ツールは返信を読み取る前に設定上の AI の提供元がこの経路かどうかを確かめ、別の提供元に変わっていればそこで止まります。

案の対象になった返信1件ごとに、AI へ送るのは次の6項目です。

  • 返信のポストID（X で公開されている番号）
  • 元の投稿の本文（先頭の @ユーザー名 を除いたもの）
  • 返信の本文（先頭の @ユーザー名 を除いたもの）
  • 言語（ja か en）
  • 送信状態を表す固定の文字列（「まだ送っていない、本人が送る」という意味）
  • 上のポストID、2つの本文、言語から計算した照合用のハッシュ値（SHA-256）

元の投稿のポストID、相手のユーザーID、表示名、ユーザー名、公開設定の値は、この6項目に入っていません。

あわせて、案の書き方を決めた固定の文章（キャラクターの口調、URL や @ を書かないなどの決まり）を送ります。その中で、返信本文に指示のような文が書かれていてもデータとして扱うよう AI に指示しています。通信に必要な技術的な項目（モデル名、設定値、リクエストの識別番号など）も一緒に送られます。

送る直前に、ツールは実際の送信内容がこの固定の文章と6項目のデータだけになっているかを照合し、一致しなければ送りません。運営者のメモや記憶データ、配信で使う視聴者の記憶、ほかの会話の履歴、プロフィール、DM は送りません。AI にはツールを操作する権限を与えません。依頼は1回の処理につき1回だけで、失敗しても再送や別の AI への切り替えはしません。

OpenAI に届いたデータの扱いは、OpenAI の規約と設定によります。こちらから OpenAI 側のデータを消す仕組みはありません。

案ができなかったとき

AI が応答しない、エラーになる、決めた形式に合わない、URL や @ を含む、長すぎる、といった場合は、その回の結果を使わず、案は表示されません。AI が一部の返信に案を返さなかった場合も、その返信には案がありません。こうした返信は、ポストIDと理由（案が返らなかった、期限切れなど）が運営者の手元に記録されます。

送信は運営者が手で行います

確認画面は公開していない運営者の手元のページで、元の投稿、受け取った返信、返信案（英語の案には日本語訳）を並べて表示します。運営者が本文を読んで確認欄にチェックを入れ、「Xで開いて送信する」を押すと、X の返信入力画面が案の文章入りで開きます。投稿ボタンを押すのは運営者です。案を書き換えるとチェックが外れ、確認し直すまで開けません。案を使わずに返信しないこともあります。

保存と表示の期限

返信案ツールは、次のデータを運営者の手元のコンピューターにファイルとして保存します。

  • 案の対象にした返信ごとの、上の6項目のデータ
  • 同じ返信と元の投稿の、先頭の @ユーザー名 を含む本文（確認画面の表示用で、AI には送りません）
  • AI が作った返信案（英語の案は日本語訳も）
  • 処理済みのメンションのポストID（直近2000件）と、対象外や期限切れなどの記録（直近200件、ポストIDと理由）
  • 公開と確認できなかった投稿の記録（ポストID、記録した時刻、理由の分類名）
  • X API と AI の利用量を管理する台帳（ポストIDを含む識別子を記録します）

相手のユーザーID、表示名、ユーザー名を、これらのファイルの項目として保存することはありません（本文の中に書かれた @ユーザー名 は、上のとおり本文と一緒に残ります）。

返信案には、読み取りから24時間の表示期限があります（下の収集期間の終わりが先なら、そこまで）。期限を過ぎると確認画面に案は出なくなり、X を開くボタンも押せなくなります。期限より後に届いた AI の応答は保存しません。

この24時間は表示と送信の期限で、ファイルの保存期限ではありません。期限が来てもファイルは自動では消えません。このツールには保存したファイルを削除する処理がなく、運営者が手で消すまで残ります。

現在のプログラムでは、X から読み取る期間は2026年11月4日 23時07分（日本時間）までと決まっていて、それより後は読み取りをしません。

削除や除外のご希望

ご自身の返信について、保存データの削除や今後の対象からの除外を希望される場合は、トップページのお問い合わせ欄からご連絡ください。運営者が内容を確認し、手作業で対応を検討します。自動で削除する仕組みはありません。すでに OpenAI に送った内容や、X 上のご自身の投稿を、こちらから消すことはできません。
